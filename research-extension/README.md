# Wine Atlas: экспериментальный браузерный сбор исследования

Расширение собирает видимые данные с сайтов и сохраняет их локально. Python обрабатывает выгрузку и добавляет подтверждённые записи в каталог.

1. В Chrome откройте `chrome://extensions`, включите режим разработчика и загрузите распакованную папку `research-extension`.
2. В меню расширения выберите «Собрать оценки критиков», «Обойти магазины» или «Собрать все источники». Предоставьте доступ к сайтам выбранного режима.
3. Расширение открывает до двух сайтов критиков или до девяти разных магазинов одновременно. В общем режиме магазинная фаза начинается после фазы критиков. Для каждого домена используется одна фоновая вкладка за раз с паузой в пять секунд между страницами. Окно расширения можно закрыть. На каждой стартовой подборке обход ограничен тремя страницами каталога и обычно десятью карточками на страницу. Для SimpleWine доступны до шести страниц и 150 видимых карточек на страницу. Для архива Wine Spectator доступно до 30 карточек на страницу. Если сайт не показывает доступную ссылку на следующую страницу, обход прекращается. Прогресс хранится локально.
4. При блокировке или авторизации адрес получает статус `blocked`, а очередь переходит к другим страницам. После разрешённого пользователем получения доступа можно запустить сбор заново. По завершении браузер скачивает JSON; его также можно скачать кнопкой.
5. Для сводки выполните `python scripts/report_research_capture.py путь-к-файлу.json`. Для проверки совпадений и предложений запустите `python scripts/import_research.py путь-к-файлу.json --report research-report.json`. Команда с `--apply` добавляет подходящие записи в `data/discovered-wines.json`. Для повторной обработки сохранённого среза используйте `--rates` со снимком XML ЦБ того же дня. Для проверенных вручную вариантов написания можно передать `--aliases` с JSON вида `{"https://…": "Единое название"}`.

Выгрузка содержит адреса без параметров, заголовок, выбранные видимые фрагменты и найденные ссылки. Она может содержать текст закрытых страниц, которые вы открыли под своей учётной записью: проверяйте её до передачи кому-либо. Cookies, HTTP-заголовки и полный HTML не сохраняются.

Автоматический импорт использует структурированные наблюдения с поддерживаемых страниц Wine Enthusiast, Falstaff, Vinous, Sabonis, Vinissimo, WineStyle и Luding. Для Decanter, DWWA, IWSC, James Suckling и Jancis Robinson включён предварительный разбор явных числовых шкал. Остальные источники дают ссылки и фрагменты для проверки. Пагинация поддерживается при наличии ссылки на следующую страницу. Сайты, где список загружается кнопкой, за подпиской или через динамические фильтры, могут дать неполный результат. Статус `needs_review` описывает сбор фрагмента, до проверки импортером.

Первая фаза формирует очередь для точного поиска винтажей в магазинах. Архив первичных фактов и способ пересобрать очередь описаны в [отчёте по критикам](../docs/critic-stage-2026-11-24.md).

Импорт очереди и нескольких выгрузок магазинов работает одной командой.

```powershell
python scripts/import_research.py first.json second.json --critic-queue critic-queue.json --rates rates.xml --report import-preview.json
```

`--rates` нужен для повторной проверки по сохранённому курсу. Без него импортёр запрашивает курс Банка России на дату наблюдения в магазине. В отчёте `retailer_matches` указаны результаты для винтажей, прошедших фильтры критиков. Заказ без подтверждения наличия на месте остаётся отдельным состоянием. Для Luding учитывается наличие у поставщика при выбранном Санкт-Петербурге. Параметр `--apply` переносит новые подтверждённые позиции в каталог с учётом существующих записей и исключений владельца.

Версия 0.1.3 сохраняет видимые поля карточек SimpleWine, AST.WINE, «Ароматного мира», «Винлаба» и Joia. Импортёр требует подтверждённый Санкт-Петербург, конкретный винтаж, цену, объём и наличие. Старые выгрузки поддерживаются. Карточки из старых выгрузок с неполными полями остаются в отчёте для проверки.

В режиме «Обойти магазины» приоритет ссылок можно взять из последнего завершённого сбора критиков. JSON содержит наблюдения нового запуска. Скрипт `auto_research.py` также обходит разные магазины параллельно и соблюдает паузу и robots.txt отдельно для каждого сайта.

Версия 0.1.5 обходит в SimpleWine две подборки: вина до 5000 ₽ и товары по числовому фильтру 90–95. Фильтр служит дополнительным входом для поиска, а общий порог каталога остаётся 85/100. В блоке `retailer_rating_leads` отчёта собраны оценки, указанные магазином, и запросы для проверки у издателей. Эти записи требуют подтверждения первоисточником. В `coverage` отчёта видны обнаруженные и поставленные в очередь ссылки, достигнутые лимиты и число извлечённых числовых оценок по каждому источнику. Количество обработанных страниц измеряет глубину обхода этого запуска.

Версия 0.1.6 начинает обход с открытых публикаций, где видны числовые баллы конкретных винтажей. Для Concours Mondial de Bruxelles отчёт сохраняет опубликованные медали в `competition_medal_leads`. Импорт требует числовой балл и подтверждённое окно употребления из источников для конкретного вина и года. Статистика магазинов в `coverage` показывает разобранные предложения и количество предложений с наличием в Петербурге до 5000 ₽.

Версия 0.1.7 проверяет розничный каталог JOIA Wine Store и открытую подборку Vinous. Для JOIA выбранный город считывается из переключателя в шапке. Винтаж подтверждается полем урожая или выбранным миллезимом. Цифры в названии вина и годы приведённых магазином оценок не используются как год продаваемой бутылки. Большие выгрузки сохраняются через временную страницу расширения с Blob URL. Расширение проверяет итоговый статус скачивания.

## Матрица винтажей и магазинов

Версия 0.1.8 повторяет временно неудавшиеся операции с вкладками Chrome. Для SimpleWine в очередь попадают все ссылки на товары, видимые на странице, в пределах 150 ссылок. Обход поддерживает до шести доступных страниц на подборку.

Скрипт матрицы берёт все вина с числовой оценкой от 85/100 по доступным разборам критиков. Карточки SimpleWine с указанием критика также включаются, если на них есть конкретный урожай. Их атрибуция отмечена как заявление магазина. Размер бутылки остаётся атрибутом предложения. Порог цены, наличие и окно употребления оцениваются для каждой строки отдельно.

~~~powershell
python scripts/research_sitemaps.py --output store-indexes.json
python scripts/research_matrix.py research.json --rates rates.xml --indexes store-indexes.json --json matrix.json --html matrix.html --plan store-search.json
~~~

В меню расширения выберите `store-search.json` в поле «JSON списка винтажей» и нажмите «Искать по каждому магазину». После предоставления доступа к сайтам поиск продолжается в фоне. Для запроса проверяются до трёх доступных страниц выдачи и до пяти карточек на страницу. Если полный запрос вернул явную пустую выдачу, расширение пробует один более короткий запрос. Кандидаты из карты сайта также открываются по прямой ссылке. Временные ошибки, ограничение доступа и нераспознанная выдача сохраняются с адресом и временем.

Передайте первоначальную и новую выгрузки команде матрицы вместе. Если расширение сохранило несколько частей JSON, передайте все части. Похожий адрес из карты сайта показывает кандидата для проверки. Цена, наличие и год выводятся по доказательствам на карточке. Пустая выдача записывается только при явном сообщении сайта.

У Luding наличие у поставщика при явно выбранном городе Санкт-Петербург считается допустимым состоянием наличия для последующей проверки; этот статус должен сохраняться отдельно от наличия в конкретном магазине.
