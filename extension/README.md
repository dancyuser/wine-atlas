# Wine Atlas - пакетная автовыгрузка Chrome / Edge

**124 вина, одна кнопка.** Для сбора не нужно скачивать JSON-каталог, вручную открывать 120 ссылок, подтверждать каждый винтаж или отдельно экспортировать результаты. Каталог 124 адресов встроен в расширение `targets.json`.

## Установка (один раз)

1. Скачать [ZIP репозитория](https://github.com/dancyuser/wine-atlas/archive/refs/heads/main.zip) и распаковать.
2. Chrome: `chrome://extensions`; Edge: `edge://extensions`.
3. Включить режим разработчика и нажать **Загрузить распакованное расширение** (`Load unpacked`).
4. Указать **каталог `extension`**, не корень репозитория.

## Запуск

1. Открыть значок расширения **Wine Atlas - автовыгрузка**.
2. Нажать **«Собрать все 124 вина»** **один раз**.
3. Можно закрыть popup; расширение продолжит работу в Chrome, последовательно открывая **одну неактивную вкладку на одну карточку**. Оставьте браузер включённым.
4. Когда счётчик достигнет 124, расширение **само сохранит** `wine-atlas-capture-YYYY-MM-DD-ID.json` в стандартную папку «Загрузки» браузера. Если пользователь остановит сбор, сохранится частичный JSON. После перезапуска браузера можно продолжить сохранённое задание.
5. Состояние: `Точных`, `Требуют проверки`, `Ошибок`. Для карточек с CAPTCHA/HTTP-блокировкой/редиректом отчёт сохраняет причину вместо чужих данных.

**Никаких кликов по отдельным винам не требуется.** Периодичность: одна открытая вкладка за раз и пауза между карточками, чтобы не перегружать сайты. Автоматический сбор **не гарантирует доступность заблокированных страниц**, не обходит CAPTCHA/авторизацию и не использует недокументированные API.

## Данные о цене и наличии (исправление по реальному экспорту)

Исходный запуск расширения \`wine-atlas-capture-2026-11-23-1795461909127.json\` завершил обработку 124 карточек, но **120 из 123 снимков не содержали Product/Offer JSON-LD**. Поэтому прежняя версия расширения не получила текущие цены WineStyle, несмотря на наличие цен на страницах.

Теперь для \`spb.winestyle.ru\` расширение дополнительно читает **только основной блок товара** \`.o-productpage-info__price .m-productpage-price\`, извлекает однозначную сумму с символом ₽ и явно указанный статус «В наличии» либо «Ожидаем поступление/Нет в наличии». Цена из карточек рекомендаций и «цена от ...» не подходит. Первоначальная цена записывается лишь при наличии отдельно помеченной зачёркнутой цены в том же блоке. Если цены или два источника противоречат, импорт блокируется.

После одного повторного пакетного запуска **«Собрать все 124 вина»** и загрузки нового JSON информация о ценах и наличии может быть импортирована с проверкой URL, названия, года и объёма. Это необходимо: в старом JSON видимые цены не записаны, восстановить их достоверно задним числом из него нельзя. Сервис может изменить цену/наличие до следующей проверки; дата наблюдения сохраняется.

## Как устроена проверка и импорт

Расширение сохраняет отдельный снимок для каждой обработанной страницы:

- идентификатор вина, целевой и фактический адреса, дата/время;
- заголовок карточки, явно обозначенные характеристики, Product / Offer JSON-LD;
- кандидата на изображение **без утверждения прав на использование**;
- категорию точности: `exact`, `needs_review`, `rejected`, `blocked`, `error`;
- полный перечень ошибок и оригинальные URL.

Для **точного** совпадения требуются исходный URL (без подмены винтажа), характерные слова названия, указанный год урожая и правильный объём. При противоречии или неполной JSON-LD-разметке цена не обновляется. Невинтажные вина (год отсутствует) **собираются**, но без ручной проверки не импортируются автоматически как точный винтаж.

Сохранённый JSON можно загрузить сюда или обработать локально:

```bash
python scripts/import_manual_capture.py ~/Downloads/wine-atlas-capture-YYYY-MM-DD-ID.json
python scripts/import_manual_capture.py ~/Downloads/wine-atlas-capture-YYYY-MM-DD-ID.json --apply
python scripts/validate_catalog.py
python scripts/validate_enrichment.py
```

Первая команда - безопасный предпросмотр, вторая - импорт доказанных характеристик и точных предложений. Исторические цены не переписываются. Исправления классификатора сохраняются в `data/overrides.json`; по непроверенным вариантам импорт не делается. `--apply` **не публикует код в GitHub**: изменения надо зафиксировать отдельным коммитом.

## Безопасность и ограничения

- Manifest V3, фоновой service worker, `chrome.tabs`, `chrome.scripting`, `chrome.storage`, `chrome.alarms`, `chrome.downloads` и **явные права только на четыре источника из списка**: `spb.winestyle.ru`, `ast.wine`, `ladogawine.ru`, `vinissimo.biz`.
- Расширение не сохраняет cookies, пароли, токены, заголовки HTTP, весь HTML, снимки чужих вкладок или сетевые запросы. Query-параметры URL редактируются, чтобы не экспортировать секреты; URL с подменённым query не считается точным совпадением.
- Не запускает параллельную пачку 124 вкладок; не обходит ограничения сайтов и сохраняет отказ доступа как отказ.
- Цена до скидки только при наличии явно указанного правильного oldPrice на странице, не на основе `highPrice` или MSRP; рейтинги критиков и чужие фотографии автоматически **не публикуются**.
- Сохранённые наблюдения локальны. Данные никуда не отправляются, пока пользователь не загрузит JSON самостоятельно.
- Изменение `data/wines.json` требует проверки тестами и выпуска сайта. Прямого доступа к вашему GitHub из браузерного расширения нет.

## Разработчикам

```bash
node --check extension/background.js
node --check extension/batch_core.js
node --check extension/capture.js
node --check extension/popup.js
node scripts/test_extension_capture.cjs
node scripts/test_batch_core.cjs
python -m unittest discover -s scripts -p 'test_import_manual_capture.py' -v
python -m unittest discover -s scripts -p 'test_wine_classifier.py' -v
```

`targets.json` соответствует исходному файлу `data/wines.json` на момент сборки расширения. После изменения состава карточек его нужно пересоздать, иначе нарушится точность сопоставления.
