# Винный атлас

Статический каталог вина из личного списка и отдельной исследовательской подборки для Санкт-Петербурга. Страница работает без сервера, базы данных, токенов и сторонних JS-библиотек.

## Возможности

- Фильтры по стране, сорту винограда, стилю, гастрономическим сочетаниям; поиск и сортировка.
- Отдельные разделы для личного списка и исследовательской подборки.
- Избранное хранится **только в браузере** через `localStorage`.
- Ссылки на карточки магазинов.
- Цена и цена до скидки (если сведения подтверждены); всегда указаны дата и статус. Исторические отметки **14.11.2026** не обозначены как актуальные.
- Адаптивная верстка с семантической разметкой.

## Исходные данные и ограничения

`data/wines.json` содержит нормализованные записи. Сведения взяты из предоставленного пользователем документа «Виш-лист (Алкоголь)»; для обновления можно использовать текстовый экспорт документа `source.txt`, хранящийся локально у владельца. Исходный документ не публикуется в репозитории. Из основного списка исключены три позиции джина; повторные идентичные ссылки устранены. Некоторые «разделы по сортам» документа включают ассамбляжи и другие вина: `section` не означает гарантированный сорт винограда. Неустановленные сорта и страны оставлены пустыми. Гастрономические сочетания — рекомендации по типу, **не подтвержденные характеристики производителя**.

При проверке 22.11.2026 первые две тестовые страницы WineStyle ответили HTTP 200, третья — HTTP 403. Сбор остановлен на всём домене; актуальные цены и характеристики не подтверждены. Поэтому `price_rub`, `regular_price_rub` и `price_checked_at` для таких записей равны `null`. Значения `reference_price_rub`, `reference_regular_price_rub`, `reference_date` — **архивный срез**, а не цена «сейчас». Текущие остатки не подтверждаются и не отображаются.

Сайт — справочник, не магазин, не предназначен для оформления онлайн-продажи спиртного. **Вопрос о допустимости публичного размещения ссылок на цены и продавцов алкогольной продукции в РФ требует отдельной правовой оценки** в свете ст. 21 Федерального закона № 38-ФЗ «О рекламе». На сайте нет рекламных баннеров, ранжирования по коммерческому размещению, аффилиатных ссылок или призывов к покупке.

## Локальный запуск

```bash
python -m http.server 8000
```

Открыть `http://localhost:8000` из корня репозитория. Прямое открытие `index.html` через `file://` не работает из-за запретов браузера на чтение JSON через `fetch()`.

## Публикация на GitHub Pages

1. Создать **публичный** репозиторий, например `wine-atlas`.
2. Загрузить содержимое этого каталога в ветку `main`.
3. В `Settings → Pages → Build and deployment → Source` выбрать **GitHub Actions**.
4. Запустить `Deploy static wine catalog`, если он не стартовал сам. Дождаться `Success`.
5. Сайт появится по адресу GitHub Pages, указанному в настройках Pages или в результате workflow.

Предусмотренный workflow `.github/workflows/pages.yml` публикует сайт. Публикация не выполняется автоматически только от наличия ZIP-файла.

## Обновление списка

Поместить текстовый экспорт документа как `source.txt` в корень каталога, затем выполнить:

```bash
python scripts/build_catalog.py source.txt
```

Генератор сохраняет ранее проверенные текущие цены для совпадающих стабильных ID товаров и адресов магазинов. Перед массовым обновлением всё же рекомендуется резервная копия. Стабильные исправления атрибутов по `id` записывайте в `data/overrides.json`.

## Проверка цен

В `Actions` доступен **ручной** workflow `Refresh prices (manual)`; он запрашивает только публичные страницы, которые разрешает `robots.txt`, и читает цены из JSON-LD Product/Offer с валютой RUB. WineStyle исключён из старого обновлятора и обслуживается отдельным обработчиком ниже. Без достоверного поля он оставляет `null`, не угадывает цену и не пытается обходить защиту сайта. Оригинальная цена заполняется только при явном `oldPrice`, `previousPrice` или `originalPrice` внутри того же offer; `highPrice` не считается старой ценой. Ограничение — нет поддержки JS-ценообразования, региональной аутентификации и скрытых API.

Перед запуском проверьте условия использования каждого интернет-магазина. Расписание обновления **намеренно не включено**, пока не подтверждено право и возможность автоматического сбора цен. Доступ к Winestyle нужно проверить в среде выполнения GitHub Actions отдельно.

Для локальной проверки первых 5 разрешенных URL:

```bash
python scripts/update_prices.py --limit 5 --dry-run
```

## Структура

- `index.html` — статическая страница
- `styles.css` — адаптивная тема
- `app.js` — локальный фильтр, карточки и избранное
- `data/wines.json` — каталог с датированными ценами
- `data/overrides.json` — проверенные ручные правки
- `scripts/build_catalog.py` — импорт данных из текстового экспорта документа
- `scripts/update_prices.py` — консервативная попытка извлечения публичных актуальных цен
- `.github/workflows/pages.yml` — GitHub Pages
- `.github/workflows/refresh-prices.yml` — ручное обновление цен

## Обогащение WineStyle и результат от 22.11.2026

[Подробный отчёт](reports/WINESTYLE-2026-11-22.md). В каталоге 163 вина, из них 122 со ссылками WineStyle. После HTTP 403 на третьей тестовой странице обращения ко всему домену прекращены. Новых подтверждённых цен, скидок и характеристик: **0**. Два ответа HTTP 200 не считаются верифицированными карточками: полный HTML при первоначальной пробе не сохранён, поля не проверены. Этот результат не означает завершённого обогащения.

Исходный JSON сохранён побайтно в `data/backups/wines.before-winestyle-2026-11-22.json`. В рабочий JSON добавлены только `stores[].enrichment_status` и сводка `winestyle_check`; все исходные значения сохранены. `reports/winestyle-access.json` хранит запрет дальнейших запросов после блокировки. Повторный запуск, включая `--headed`, не меняет способ доступа и не пытается обойти остановку.

```bash
pip install -r scripts/requirements-enrichment.txt
python scripts/enrich_winestyle.py --domain winestyle.ru --limit 3 --dry-run --delay 3
python scripts/enrich_winestyle.py --domain winestyle.ru --delay 3
```

Оба запуска выполнены: код возврата 2 означает остановку доступа. `--dry-run` не меняет ни каталог, ни состояние доступа, ни JSON-отчёты. Полный запуск записывает `reports/winestyle-run.json`. Другие коды: 0 — без ошибок; 1 — ошибки отдельных карточек. `--limit 0` означает все записи, отрицательное ограничение и задержки меньше секунды отклоняются.

Для разрешённых JS-страниц предусмотрен `--headed`: обычный видимый Chromium Playwright (`pip install playwright`, затем `playwright install chromium`), без использования профиля пользователя, CAPTCHA-решателей и скрытых API. Реальная ветка браузерного извлечения WineStyle в этой сессии не запускалась после 403 и на живом сайте не подтверждена.

Перед любым будущим сетевым сбором нужно установить, что блокировка снята обычным доступом, и прочитать действующие условия сайта. Пока состояние `blocked=true`, скрипт не обращается к домену. После разрешённого восстановления доступа состояние должен пересмотреть владелец, сохранив прежний отчёт. Нельзя снимать его для обхода запрета. Для сетевого режима дополнительно нужен `--policy-file reviewed-policy.json`: объект с `allowed: true`, фактически прочитанным `terms_url`, датой `reviewed_at` и содержательным `note`. Это запись ручной проверки, не автоматический вывод о разрешении. Перед карточками скрипт читает robots.txt заново; при невозможности прочитать правила прекращает сбор. Условия и полные правила robots.txt в текущей сессии не установлены: robots вернул 200, но сохранился только фрагмент.

### Допустимый ручной путь

Если обычный ручной просмотр публичной страницы разрешён сайтом, владелец может сверить название, производителя, год и объём, сохранить разрешённый HTML страницы в UTF-8 и дату. Не обходить ограничения; при недоступности запросить разрешение/экспорт у WineStyle. Не переносить фотографии без разрешения.

Сохранённые вручную файлы можно обработать **без сетевых обращений**. Папка `manual/` должна содержать `manifest.json` (массив объектов `url`, `file`, `checked_at` в формате YYYY-MM-DD) и соответствующие HTML-файлы. Адрес должен в точности совпадать с URL магазина в каталоге; файл должен находиться внутри этой папки. Сначала:

```bash
python scripts/enrich_winestyle.py --input-dir manual --domain winestyle.ru --dry-run
python scripts/enrich_winestyle.py --input-dir manual --domain winestyle.ru
python scripts/validate_catalog.py
```

Отсутствующая карточка пропускается. Несовпадение товара, года, производителя или известного объёма отклоняется. Парсер требует достаточно полных структурированных данных; он намеренно отклоняет неустановленную идентичность, поэтому пользовательский HTML может потребовать дополнения адаптера DOM. До успешной проверки трёх реальных карточек массовое извлечение не считается проверенным.

### Совместимая схема и отображение

Исходные `id`, `title`, `year`, `country`, `grapes`, `type`, `section`, `pairings`, `description` и `stores[].url` сохранены. Страна/объём могут заполняться обработчиком только если прежнее значение пусто и нет ручного переопределения. Раздел списка никогда не используется как доказательство сорта или страны. Новые сведения сохраняются отдельно в `stores[].product_details`: полное имя, производитель, год, страна/регион/апелласьон, сорта с долями в исходном тексте, цвет/тип/сладость, крепость/объём, вкус/аромат/сочетания, URL фотографии, достоверное региональное наличие либо null, URL источника, дата и происхождение каждого поля. Отсутствующие значения остаются null; прежние подтверждённые поля сохраняют собственную дату в `field_checked_at`.

Новая текущая цена относится к тому же Product и Offer, имеет RUB/RUR и явное конечное значение. Диапазоны, AggregateOffer, другая валюта/фасовка/URL, NaN, Infinity и нецелые рубли не принимаются. До-скидочная цена берётся только из явного oldPrice/previousPrice/originalPrice того же предложения, никогда из highPrice/MSRP. При неизвестной новой цене прежний подтверждённый снимок с его датой сохраняется. `reference_price_rub`, `reference_regular_price_rub`, `reference_date` остаются архивом. Повторный импорт через build_catalog сохраняет архив, текущие цены, сведения и статусы магазинов.

Интерфейс показывает индивидуальный текст из каталога, а при отсутствии описания сообщает об этом. Исходные характеристики обозначены как требующие сверки; архивные сведения о наличии не выдаются за новые. Подтверждённые факты источника отделены от типовых сочетаний. Изображение показывается только при `image_usage_allowed: true` **и** непустом `image_permission_source`; иначе остаётся иллюстрация. URL картинки сам по себе не доказывает разрешение. Пока разрешения не получены, сборщик устанавливает false.

### Проверки

```bash
python scripts/validate_catalog.py
python -m unittest discover -s tests -v
node --check app.js
python tests/check_site.py
```

Валидация сопоставляет каталог с замороженным оригиналом, проверяет ID/URL, архив, типы полей, цены, даты, принадлежность сведений товару и разрешение изображений. 20 тестов парсера/сохранности используют явно синтетические фикстуры. Браузерная проверка запускает видимый системный Edge (Chromium) на локальном сервере, блокирует внешнюю сеть и проверяет реальные 163 карточки, фильтры, сортировку, избранное после перезагрузки, пустой результат, мобильную ширину 390 px. Отдельная проверка отображения подтверждённых данных использует фикстуру только в памяти; в каталог она не записывается. Нужны Playwright и установленный Microsoft Edge. Все проверки пройдены 22.11.2026.
